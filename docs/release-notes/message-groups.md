# メッセージ入力と最大5件のまとめ送信

一斉配信、シナリオの直接入力、リマインダー、個別チャットに共通のメッセージ入力を導入。
テキストは文章、画像はアップロード／画像URL、FlexはJSONとプレビューを表示する。
最大5件を混在させ、追加・削除・並び替えできる。個別チャットは「複数・Flex」から開く。
従来の個別チャットの画像＋文章も1リクエストにまとめる。

保存・送信時に件数、空欄、画像URL、FlexのJSON形式を検査する。LINE側のFlexレイアウト等の完全な検証はAPIが行う。
一斉配信のテスト送信、予約・キュー、複数アカウントの重複除外、シナリオの即時・予約・reply、リマインダーに同じ順序の配列を渡す。
友だちの名前などの差し込みとリンク計測はメッセージごとに適用し、画像URLは計測リンクに変えない。

## 保存形式と通数

既存の1件のデータ形式は変更しない。複数の場合は既存の `message_content` に
`{"$lineHarnessMessages":1,"items":[{"messageType":"text","messageContent":"..."},...]}` を保存する。
`message_type` は先頭メッセージの種類。共通codecで展開してからLINEへ送信し、保存用JSON自体は送らない。
テーブルの再作成・データ移行は不要。

送信ログは受信者×送信1回につき1行とし、履歴表示で各メッセージに展開する。
通数・配信の成功人数・再開位置はメッセージの個数で増やさない。
既存の専用キャンペーン（2026年9月の固定配信）は従来の単一メッセージ制約を維持する。

## リリース時の注意

Workerと管理画面をセットで更新する。先にWorker、次に管理画面を公開する。
複数メッセージを保存した後、旧Workerだけへ戻すと保存用JSONを正しく処理できないため、単独での巻き戻しは不可。
実際の友だちへのLINE送信を伴わず、送信APIの呼び出し内容を結合テストで検証する。

## 検証

実SQLiteを使う結合テストで、5件の順序、1回のAPI呼び出し、1行のログ、6件の拒否、
アカウント分離、同一人物の重複除外、シナリオ・リマインダーの完了と再実行を検証する。
入力・プレビューはReactのサーバーレンダリングで検証。ブラウザ操作による検証は行っていない。
